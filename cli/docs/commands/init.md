# `azd app init`

Initialize azure.yaml for local development with `azd app run`.

## Overview

Scans your project directory to detect services, languages, frameworks, and dependencies, then generates or enriches an `azure.yaml` configuration file with all the settings needed for `azd app run`.

## Usage

```bash
azd app init [flags]
```

## Modes

### New Project (no azure.yaml)
Creates a complete `azure.yaml` from scratch based on detected project structure, including services, ports, commands, prerequisites, and infrastructure dependencies.

### Existing Project (azure.yaml exists)
Non-destructively enriches the existing file, adds missing `ports`, `command`, `language`, and `uses` fields to services without overwriting anything already configured.

## Examples

```bash
# Initialize in current directory
azd app init

# Preview what would be generated (no file changes)
azd app init --dry-run

# Force overwrite of existing services section
azd app init --force
```

## Flags

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--dry-run` | bool | `false` | Show what would be generated without writing files |
| `--force` | bool | `false` | Overwrite existing services section in azure.yaml |

## Detection Capabilities

### Languages & Frameworks

| Language | Detection File | Frameworks Detected |
|----------|---------------|-------------------|
| Node.js/TypeScript | `package.json` | Next.js, Nuxt, Angular, Vite, React, Express, Fastify, Hono, Koa, NestJS, Astro, SvelteKit |
| Python | `requirements.txt`, `pyproject.toml`, `Pipfile` | FastAPI, Flask, Django, Streamlit, Starlette |
| .NET | `*.csproj`, `*.sln` | ASP.NET Core (all) |
| Go | `go.mod` | Gin, Echo, Fiber, Gorilla Mux, Connect-RPC |
| Azure Functions | `host.json` | Node.js, Python, .NET, Java, Logic Apps |

### Infrastructure Dependencies (`uses`)

Init scans package files to detect infrastructure dependencies and adds them to the `uses` field:

| Dependency | Libraries Detected |
|-----------|-------------------|
| `postgres` | pg, pgx, psycopg2, asyncpg, Npgsql, jackc/pgx, gorm/postgres |
| `redis` | ioredis, redis, aioredis, StackExchange.Redis, go-redis |
| `mongodb` | mongoose, pymongo, motor, MongoDB.Driver, mongo-driver |
| `mysql` | mysql2, mysqlclient, aiomysql, MySql.Data, go-sql-driver/mysql |
| `rabbitmq` | amqplib, pika, RabbitMQ.Client, amqp091-go |
| `kafka` | kafkajs, confluent-kafka, IBM/sarama, segmentio/kafka-go |
| `servicebus` | @azure/service-bus, azure-servicebus, Azure.Messaging.ServiceBus |
| `storage` | @azure/storage-blob, azure-storage-blob, Azure.Storage.Blobs |
| `cosmosdb` | @azure/cosmos, azure-cosmos, Microsoft.Azure.Cosmos |

### Package Manager Detection

Automatically detects and uses the correct package manager:
- **Node.js**: npm, pnpm, yarn (from lockfiles and `packageManager` field)
- **Python**: pip, uv, poetry, pipenv (from lockfiles and config)

## Output

### Generated azure.yaml Structure

```yaml
# Generated by azd app init
# yaml-language-server: $schema=https://raw.githubusercontent.com/jongio/azd-app/main/schemas/v1.1/azure.yaml.json

name: my-project

reqs:
  - name: node
  - name: pnpm
  - name: python
  - name: go

services:
  api:
    language: ts
    project: ./api
    command: "pnpm run dev"
    ports:
      - "3000"
    uses:
      - "postgres"
      - "redis"

  web:
    language: ts
    project: ./web
    command: "pnpm run dev"
    ports:
      - "5173"

  worker:
    language: python
    project: ./worker
    command: "uvicorn main:app --reload --port 8000"
    ports:
      - "8000"
    uses:
      - "mongodb"
```

### JSON Output

With `--output json`, returns structured detection results:

```json
{
  "services": [
    {
      "name": "api",
      "language": "ts",
      "framework": "Express",
      "project": "api",
      "ports": ["3000"],
      "command": "npm run dev",
      "packageManager": "npm",
      "type": "http",
      "uses": ["postgres", "redis"]
    }
  ],
  "azureYamlPath": "/path/to/azure.yaml",
  "created": true,
  "enriched": false
}
```

## Behavior

### Service Deduplication

When a directory matches multiple detectors (e.g., a Python Functions app has both `host.json` and `requirements.txt`), the most specific detector wins:

1. Azure Functions / Logic Apps (most specific)
2. Node.js / TypeScript
3. Python
4. .NET
5. Go

### Workspace Handling

For Node.js monorepos with workspaces, init detects child packages as individual services rather than treating the workspace root as a single service.

### Next Steps After Init

```bash
# 1. Review and adjust the generated azure.yaml
#    (ports, commands, environment variables)

# 2. Check prerequisites are installed
azd app reqs

# 3. Install dependencies
azd app deps

# 4. Start all services
azd app run
```
